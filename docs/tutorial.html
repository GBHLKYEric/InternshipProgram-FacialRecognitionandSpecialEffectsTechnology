从零学人脸视觉：给高三学生的项目教程

本教程配套源码仓库：GBHLKYEric/face_ai_project。你不需要先会编程，但需要愿意逐行运行小实验、记录结果，并用高中函数、向量和概率知识解释结果。学完的标准不是背下模型名称，而是能画出数据经过程序的路径、找出报错发生在哪里、独立完成一次可重复的实验。

先分清本项目的两层工作。本地应用用已经训练好的 YuNet/SFace 完成检测、五点定位、两张照片的相似度比较和图像特效；research/ 是训练和评估研究代码。会运行应用不等于自己训练出了 ArcFace，也不等于已达到 LFW 98.5%。最终做成了什么、还差什么，应查 验收矩阵 和 项目报告。本文讲完整知识路线；“拓展实验”不表示本机已经完成该实验。

学习路线与每次学习的方法

建议按下面的顺序推进，课时是学习安排而非性能承诺。每节先读概念，手算例子，再运行代码，最后关掉答案独立完成练习。遇到专业词先回到“输入是什么、输出是什么、用什么数据检验”三个问题。

阶段 内容 能独立做出的成果
第 1–3 次，每次约 60 分钟 电脑环境、Python、图像、向量 运行灰度程序，解释图像尺寸、像素和路径
第 4–6 次 神经网络、检测、关键点、对齐 为图片画框、画点，解释误检和漏检
第 7–9 次 人脸特征、ArcFace、数据和评估 手算余弦相似度，正确理解十折结果
第 10–12 次 训练、难例、压缩、ONNX 运行小规模训练，比较两个推理后端
第 13–15 次 特效、GAN、三维、视频 修改贴纸位置，解释 GAN 与染色的区别
第 16–18 次 Docker、GitHub、实验报告 复现实验、发布源码并说清未完成项

第一轮不要求你从零训练每个大型模型。第二轮再取得所需研究数据与硬件，按实验方案做完整训练。不要把算力不足、数据不完整产生的结果包装成论文级成绩。

第 1 课：这个系统到底在做什么

检测回答“哪里有人脸”，输出一个矩形，例如左上角 (80, 50)、宽 120、高 150。关键点回答“眼睛、鼻尖、嘴角在哪里”，输出坐标。对齐把歪着的脸旋正并缩放到统一大小。特征提取把对齐图变成一串数字。验证比较两张图是否可能属于同一人；识别是在已登记名单中寻找最相似的人。本地界面主要演示验证，没有凭空知道陌生人的姓名。

处理路径： 图像或视频帧 → 检测与关键点 → 对齐 → 特征向量 → 余弦比较。检测与关键点也用于定位贴纸、美颜与三维重建。

训练是从许多“题目+答案”调整模型参数，推理是用调整好的参数处理新输入。.py 是计算方法，.onnx/.pt 通常含结构或参数，.jpg 是数据，.json/.csv 常是配置或结果。只有源码而没有所需参数，模型通常无法直接完成任务。

练习：一张合照有三张脸，模型输出三个人脸框，但并不知道姓名。它完成了识别吗？

答案：完成了检测，尚未完成身份识别。若另外输入一张登记照，可以提取特征进行比对，但仍需阈值与误差评估。

第 2 课：Python、终端与隔离环境

终端不是“黑客窗口”，它只是用文字向电脑下达命令。Windows 的 PowerShell 中，Get-Location 查看当前位置，Get-ChildItem 查看文件，Set-Location 切换目录。路径中有空格时加引号。项目命令必须在仓库根目录执行，即能看到 app.py 的目录。

如果你在另一台电脑上学习，先安装Git和仓库支持的Python，然后在准备保存项目的目录执行 git clone https://github.com/GBHLKYEric/face_ai_project.git，再执行 Set-Location face_ai_project。本机已经有交付目录时直接进入该目录即可，无需再次下载同一份源码。

第 3 课：图像其实是数字数组

一张彩色图可以看成高×宽×3 的数字表。通常每个颜色值在 0–255。OpenCV 常按 BGR 顺序，浏览器/Pillow 常用 RGB；两者混淆会把红色和蓝色交换。NumPy 图像索引写 image[y, x]，几何坐标却常写 (x, y)。前者先行后列，后者先横后纵。

from pathlib import Path
import cv2

image = cv2.imread("assets/sample.jpg")
if image is None:
    raise FileNotFoundError("请从项目根目录运行，并检查 assets/sample.jpg")
print("高、宽、通道：", image.shape)
gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
Path("reports").mkdir(exist_ok=True)
if not cv2.imwrite("reports/gray.jpg", gray):
    raise OSError("保存灰度图失败")

灰度是把三个通道按亮度权重组合为一个。缩放改变像素数量；归一化改变数值范围，例如 image.astype('float32') / 255。很多模型还要求减去均值再除以标准差。预处理是模型的一部分：训练用了 RGB、112×112、范围 [-1,1]，推理就要一致。不要只看文件扩展名相同就认为输入正确。

练习：640×480 彩色图有多少个通道数值？答案：640×480×3=921600。若用 uint8，原始像素约 0.92 MB；JPEG 文件大小不是这个数字，因为经过压缩。

第 4 课：只用高中数学理解神经网络

先看函数 y=wx+b。给定输入 x，参数 w、b 决定输出；学习就是调整参数让预测接近答案。神经网络把许多这样的运算和非线性函数串在一起。ReLU 为 max(0,x)，它让组合能表达不止一条直线。

损失函数衡量预测错得多严重。若目标为 3、预测为 1，平方损失为 (1-3)^2=4。梯度告诉每个参数往哪里变会使损失增大；梯度下降沿相反方向走：新w = 旧w - 学习率 × 梯度。学习率过大可能震荡，太小进展慢。

训练四步：前向计算输出→计算损失→反向传播计算梯度→优化器更新参数。optimizer.zero_grad() 清掉上一批梯度；不清会无意累加。model.train() 与 model.eval() 会影响 BatchNorm、Dropout；评估时通常配 torch.no_grad() 关闭梯度以节省内存。

SGD 用一小批样本估计更新方向，动量帮助平滑；Adam 还利用梯度的一阶、二阶统计调整步长。不存在永远最好的优化器，应该控制其他变量比较。一个 epoch 表示计划遍历一轮训练数据，batch 是一次送入模型的样本；若使用重采样，epoch 中“看到的样本次数”未必等于不同文件数。

卷积用同一个小窗口在图上滑动。例如核 [1,0,-1] 可响应左右亮度差。多个卷积逐渐组合出边缘、局部纹理和更复杂结构。池化降低空间尺寸；BatchNorm 标准化中间特征并学习缩放与平移，训练和推理使用统计量的方式不同。

网络 你应掌握的关键点 本项目联系
LeNet 卷积与池化组成早期识别网络 用来建立最小概念
ResNet 输出=x+F(x) 的残差连接改善深层训练 研究识别模块用 ResNet50 提特征
MobileNet 深度可分离卷积减少计算 适合轻量推理，速度仍需实测

SIFT/HOG 是人工设计特征：SIFT 关注局部关键点，HOG 统计梯度方向；深度特征通过数据学到。传统方法不需要训练同样规模的神经网络，但对复杂任务的表达能力与适应性不同。二者都把原始像素变成适合比较的数字。

练习：w=2、梯度 g=3、学习率 0.1，新 w 是多少？答案：1.7。若 loss 下降，是否证明泛化变好？答案：不证明，可能只是记住训练集，必须看独立验证集。

第 5 课：检测、关键点与对齐

检测器通常同时学习分类和框的位置。IoU 是预测框与真实框的交集面积除以并集面积。两个 10×10 框只在横向错开 5 像素，交集 50，并集 150，IoU=1/3。NMS 按置信度保留框并去掉高度重叠的重复框；阈值过严可能压掉挤在一起的两张脸。

小脸在图片中占的像素少，直接缩小整图会让细节消失。FPN 在不同分辨率特征层融合语义；SSD 在多个尺度预测框。MTCNN 使用级联网络逐步筛候选并估计关键点；它是深度学习检测器，不宜称作纯传统图像算法。RetinaFace 是单阶段多任务方法，可以共同预测框和五点；论文中的更多分支不能假定任意名为 RetinaFace 的第三方包都实现了。RetinaFace 原论文

关键点回归有两种常见表达：直接输出 x、y，结构简单；输出每个点的热图，高值表示该位置的响应较强，保留空间信息但需要更多内存。热图只有经过适当归一化并满足建模约定时才可当作概率分布。HRNet 在多尺度分支间保留和交换高分辨率信息；SAN 用风格聚合图像与原图共同处理外观变化。五点适合粗对齐，68 点能描述嘴唇、眼睑与轮廓，稠密网格更细；点数多并不自动代表质量更高。HRNet、SAN

对齐常用相似变换：

x' = s cosθ · x - s sinθ · y + tx
y' = s sinθ · x + s cosθ · y + ty

它包含统一缩放 s、旋转 θ、平移 tx/ty。一般仿射变换是 2×3 矩阵，允许更一般的线性形变。把检测到的眼鼻嘴角映射到固定模板，可以减少姿态和位置对身份特征的干扰。不要用任意三个点去拟合强透视侧脸然后宣称还原了真实正面。

本地应用中，YuNet 给出人脸框与五点，SFace 的 alignCrop 执行所需对齐。看 app.py 时沿 检测→选择人脸→alignCrop→feature 顺序读。多人图在验证场景存在歧义，应用应要求明确的一张脸；没有检测到脸时应报告失败，不生成一个看似正常的随机相似度。

关键点评估常用归一化平均误差：NME = 所有点平均欧氏误差 / 归一化距离。300-W 官方协议使用外眼角距离；有些论文用瞳距或框大小，分母不同时不能直接比。原 300-W 标注是从 1 开始计数，OpenCV/NumPy 常从 0 开始，应只转换一次。300-W 官方协议

练习：68 点平均误差 3 像素，外眼角距离 60 像素，NME 是多少？答案：0.05，即 5%。若图像放大两倍，点误差和眼距都翻倍，NME 不变。

第 6 课：先学会分数据，再训练模型

训练集用于更新参数，验证集用于选择超参数和阈值，测试集用于最终评价。训练集和测试集出现同一文件、同一人的近重复帧，或测试时调阈值，都可能产生数据泄漏。人脸任务还应关注“身份是否重叠”：想测试对陌生人的泛化，就不能只在训练身份的新照片上自测。

CelebA 的每张图有属性标签，适合属性编辑；LFW 的官方 pairs 定义同人/异人配对，适合验证；WIDER FACE 的框适合检测；300-W 的点适合关键点回归。MS-Celeb-1M 是历史大规模识别数据来源，本次未取得可核验授权包，不从不明镜像下载。数据来源、许可与规模

数据分析至少回答：图片数、身份数、每类最少/中位/最多样本、分辨率分布、损坏文件数、正负属性占比、训练测试拆分以及重复样本。十个身份各一万张与十万个身份各一张，虽然总图数相同，却是完全不同的问题。

本次可以直接复现的统计命令为 python scripts/analyze_lfw.py --root data/lfw/lfw --output reports/lfw-distribution。它遍历本地图片路径，实际得到13233图、5749身份；其中4069个身份只有1张图，每身份中位数为1、最大值为530。打开 reports/lfw-distribution.svg：横轴是每身份图片数区间，纵轴是落在区间中的身份数量。大量身份只有极少图片、少数身份有很多图片，称为长尾分布。使用P-K采样且K≥2时，单图身份无法提供不同照片的同人正样本；复制同一文件不增加身份多样性。直方图仅证明文件数量分布，不能推断年龄/性别/族裔平衡或标签真实性。

数据增强应保留任务所需真值。左右翻转后，关键点左右名称要交换；裁剪后，框和点坐标要同时改变；颜色变化可增强照明鲁棒性，但增强过强会破坏肤色/发色属性标签。LFW 测试时不要随机增强后挑最高成绩。

身份目录示例：

data/consented_faces/
  person_001/01.jpg
  person_001/02.jpg
  person_002/01.jpg
  person_002/02.jpg

这些文件应来自本人或明确同意的参与者，并留在本地。这个目录格式可供研究代码读取，但其存在不等于它是 MS-Celeb-1M。用替代数据训练，应把数据集名称与样本数写进报告。

练习：从同一段视频截取前 500 帧训练、后 500 帧测试，是否一定独立？答案：不是，相邻帧高度相似，背景和姿态可能几乎一样。可按拍摄场次和身份划分，再核查重复。

第 7 课：用向量理解人脸识别

向量是一串数。例如 (3,4) 长度为 sqrt(3²+4²)=5，归一化后为 (0.6,0.8)，长度变成 1，方向不变。人脸模型的特征可能有 128、512 等维，无法直接画出，但同样能算长度和夹角。

两向量 a、b 的余弦相似度为 dot(a,b)/(||a||||b||)。方向一样接近 1，垂直接近 0，相反接近 -1；真实模型分数分布依模型而定。相似度不是“有多少概率是同一人”。如果要输出概率，还需要另做校准。浮点误差可能产生 1.00000005，显示时裁剪到 [-1,1] 合理，但不能用裁剪隐藏严重数值错误。

from math import sqrt

a, b = [3, 4], [4, 3]
dot = sum(x*y for x, y in zip(a, b))
norm_a = sqrt(sum(x*x for x in a))
norm_b = sqrt(sum(x*x for x in b))
print(dot / (norm_a * norm_b))  # 0.96

训练时常先把身份当作类别。Softmax 把原始分数转换成和为 1 的概率：p_i=exp(z_i)/Σ exp(z_j)，交叉熵为 -log(p_正确类)；正确类概率越低，惩罚越大。推理比较陌生人时通常去掉训练分类头，只保留特征。

对比损失让同人的距离近、异人的距离超过某个间隔。三元组由锚点 a、同人的 p、异人的 n 组成：max(0, d(a,p)-d(a,n)+m)。例：同人距离 0.4、异人 0.5、间隔 0.2，损失 0.1；要继续把异人推远或把同人拉近。

CosFace 在正确类的余弦值上减 margin：s(cosθ-m)；ArcFace 在正确类角度上加 margin：s cos(θ+m)，其他类用 s cosθ。只有目标类别被额外增加难度，迫使模型学到更紧的同类聚集和更大的类间角距。s 是尺度，m 的单位是弧度；m=0.5 约为 28.6°。ArcFace 原论文

实现常用恒等式 cos(θ+m)=cosθ cos m - sinθ sin m，再用 sinθ=sqrt(max(0,1-cos²θ))，避免直接 acos 的边界数值问题。大角度区间还需单调性分支处理；不是把公式写进去就一定训练稳定。特征和分类权重都先 L2 归一化。

本项目 research/recognition.py 提供 ResNet50、ArcFace、P-K 采样和 batch-hard triplet。P-K 采样一批取 P 个身份、每个 K 张图，保证既有同人也有异人；困难正样本是同人中距离最大的，困难负样本是异人中距离最小的。过分追逐最难样本可能追到错标签，故要检查异常图像。大规模身份时分类权重内存为 身份数×特征维度×每个数的字节数；百万类×512×4 约 2.05 GB，仅权重还未算优化器状态。Partial FC 等方法只采样部分负类别来降低开销。

练习：同图比较得到 1，是否证明系统识别人脸准确率 100%？答案：不是，只是同一输入的一致性检查。需要独立同人/异人 pairs 和固定协议。

第 8 课：正确读懂准确率、ROC、TAR@FAR 和 AP

验证阈值越高，通常越难判为同人。把异人错认成同人是误接受；把同人拒绝是误拒绝。TAR 是同人对中被正确接受的比例；FAR 是异人对中被错误接受的比例。TAR@FAR=0.001 表示在限制误接受约千分之一的阈值附近，能接受多少同人对。样本不足时，不可能可靠估计极低 FAR。

例：1,000 对同人中 950 对通过，1,000 对异人中 10 对误通过，TAR=95%，FAR=1%，总准确率 (950+990)/2000=97%。它不等于 TAR，也不能拿到另一个任务上说“识别率97%”。ROC 横轴 FAR、纵轴 TAR，扫过阈值得到曲线。AUC 描述整个曲线，不能代替某个业务阈值表现。

LFW 官方常用 6,000 pairs、十折交叉验证。第 1 折作测试时，用另外 9 折选择阈值；重复十次，然后报告十个测试准确率的均值与标准差。不能在同一测试折上找最优阈值再报成绩。缺图不能悄悄丢弃；检测失败需计数并事先声明处理方式。scikit-learn 官方 pairs 接口

对于检测，Precision=TP/(TP+FP)，Recall=TP/(TP+FN)。AP 对置信度从高到低的 precision-recall 关系进行汇总；mAP 再跨类别或 IoU 阈值平均，具体定义依协议。WIDER 有 easy/medium/hard 难度划分；COCO AP 常跨 IoU=0.50–0.95。单类别 AP50、COCO AP 和 WIDER hard AP 都不是同一个数字。

练习：模型预测 12 个框，其中 9 个正确；真实有 15 张脸。Precision=75%，Recall=60%。检测框正确还要先约定 IoU 判定和一对一匹配规则。

第 9 课：第一次训练应该怎样做

不要一开始就拿满数据跑三天。先检查能读取 1 张，再看 1 个 batch 的形状和值域，然后用很小的固定数据检查 loss 是否有限、参数是否变化、checkpoint 能否重新载入。这个阶段叫 smoke test，只检查管线。之后再进行有合理样本规模、完整轮次与独立评估的训练。

本项目身份训练命令（需要先准备合法数据）：

.\.venv\Scripts\python.exe -m research.recognition --data data/consented_faces --output runs/arcface --epochs 20 --p 8 --k 4 --device cpu

P=8、K=4 要求至少 8 个满足至少 4 张图的身份。一批共32张。若只有2人各2张，可用 --p 2 --k 2 检查程序，但不适合宣布达到人脸识别基准。CPU 训练 ResNet50 可能很慢；命令能运行不代表耗时适合课堂。GPU 可用时也要先确认显存和驱动，再选择 --device cuda。

第 10 课：量化、剪枝、蒸馏和 ONNX

FP32 通常用 32 位表示一个数，INT8 用 8 位。量化大致为 q=round(x/scale)+zero_point，推理时近似还原。范围选择不好会截断极端数值，或让常见小值分辨率过粗，所以缩小模型不保证精度不变。

动态量化在运行时处理激活范围，常作用于线性层/RNN 等支持算子。ResNet50 主体是卷积，只动态量化末端 Linear，整个模型可能不会明显变小或变快。静态量化需要代表性校准数据；QAT 在训练中模拟量化误差。PyTorch API 随版本演进，项目用哪个版本就查看对应文档，不能把新教程命令硬套进旧环境。PyTorch 量化文档

剪枝把部分参数或通道去掉。非结构化“置零”不会自动使普通稠密矩阵计算更快；结构化裁掉通道才更可能减少实际算量，但会改变网络尺寸。蒸馏让小模型学习大模型的输出或特征；学生模型仍需训练，并在独立数据上验证。

ONNX 把模型计算表达为通用计算图，ONNX Runtime 是一个执行器。导出要确定输入 N×C×H×W、颜色范围、opset 和动态维度。ONNX checker 只证明图格式合法；还需把相同输入送到 PyTorch 与 ORT，比较最大绝对误差、余弦相似度、真正任务指标。PyTorch ONNX 文档

评速度时固定设备、线程数、图像大小、batch，并先预热。重复测量报告中位数与 P95，注明是否包含解码、对齐、特效和浏览器传输。量化模型在桌面 CPU 变快，不代表手机也快。层融合减少多个相邻算子之间的开销；内存复用减少申请和拷贝；这些优化必须用 profiler 或计时证明。

第 11 课：贴纸、美颜、美妆如何跟着脸移动

两眼中心给眼镜位置，两眼距离给比例，两眼连线给旋转角 atan2(dy,dx)。帽子或皇冠放在眼睛上方一定倍数眼距的位置。这样脸变大时贴纸也变大，歪头时贴纸旋转。贴纸超出边界时必须裁剪，不能用负数组索引把它画到另一边。

透明度混合为 输出=α×贴纸+(1-α)×原图。α=0 完全透明，α=1 完全覆盖。背景为透明的 PNG 常有第四个 alpha 通道。若全图统一 α，就无法保留不规则贴纸的透明边缘；应逐像素混合。

磨皮可在脸部掩膜中混合平滑结果，双边滤波兼顾空间和颜色相近性，较能保留边缘；美白是有限度地调整亮度，注意裁剪到允许范围。口红要定位唇区后改变颜色并保留纹理。只有五点时仅知道嘴角，唇轮廓是近似形状，张嘴、侧脸、遮挡会露出局限；改用68点或面部分割能改进，不能谎称已有精确唇部分割。

视频是一帧帧图片。每帧重检位置容易抖动，可用指数平滑：平滑点_t=α×当前检测+(1-α)×上次平滑点。小 α 稳定但延迟大；大 α 灵敏但抖动明显。多张脸要先做帧间匹配，不能把上一帧甲的点平滑到下一帧乙的脸上。检测丢失应重置跟踪状态。

本项目的眼镜、皇冠、磨皮/美白、口红是几何和传统图像处理。它们可作为动态特效入门，但不等于训练了 StarGAN。彩色头发区域叠加也不等于学习了年龄变化模型。

练习：两眼位置从 (100,100),(160,100) 变成 (100,100),(220,100)，眼镜宽度应怎样变化？答案：眼距从60到120，应扩大到原来的两倍。若视频仅重复同一张图，是否验证了跟踪？答案：没有，只验证重复处理和编码。

第 12 课：GAN、属性编辑、FID 与 IS

GAN 包含生成器 G 与判别器 D。G 希望生成图像能通过 D 的判断，D 希望区分真实与生成，两者交替更新。DCGAN 用卷积结构完成生成与判断；StyleGAN 用风格控制不同层级的生成过程；StyleGAN3 进一步处理信号采样造成的混叠，改善运动时纹理相对物体的稳定性。StyleGAN3 论文

StarGAN 给 G 输入原图 x 与目标属性 c，例如发色标签，让共享网络完成多域转换。训练同时关心生成图是否自然、属性是否符合目标，以及能否变回原属性以保持内容。AttGAN 的设计强调属性约束与重建，适合在学习时比较“哪些因素应改变、哪些应保留”。不要把性别标签当成对真实个人身份的可靠判断；在本项目中它只是数据集给定的研究标签。

research/stargan.py 是教学规模实现。短时间、低分辨率、少量样本训练只能用于观察 loss 与结构，无法保证高质量属性编辑。真正实验应按 CelebA 官方拆分、记录所选属性、正负分布、训练轮次与生成样本；禁止把数据集图片上传公共仓库。StarGAN 官方实现

FID 在特征空间比较真实与生成分布的均值和协方差，大致为 均值距离平方 + 协方差差异项，通常越低越好。必须使用定义一致的特征器、同样的缩放和输入数量；几十张图的 FID 波动很大。IS 关心单张生成图被分类的确定性以及整个集合类别的多样性，不直接比较真实分布；自然图像分类器对人脸属性并非完美评价工具。FID 原论文

质量还应检查身份保持、目标属性成功率、背景是否乱变，以及遮挡与不同肤色光照下的表现。只挑最漂亮的一张属于选择性展示，不是完整评估。

练习：两次 FID 分别用100张和10,000张生成图，数值较低的那次一定更好吗？答案：不能直接得出，样本规模、预处理和特征器可能影响分数。应固定协议再比较。

第 13 课：扩散模型、文本条件与参考图条件

扩散模型先定义逐步给图像加噪的过程，再训练网络从某个噪声强度下的图像预测噪声或相应去噪目标。生成时从噪声出发多步去噪。可以把它理解为“反复修正”，但每步不是凭空识别真实被遮盖内容，而是在训练分布和条件下采样。DDPM 论文

条件可以是属性标签、文本编码、姿态图或参考图。条件控制并不保证输出完全符合，也可能改变身份。Stable Diffusion 是相关的潜空间扩散模型系列，具体版本与权重各有许可；本项目讲其原理，没有把几何特效称为扩散生成。

练习：输入“让头发变蓝”，模型把人物换成另一张脸，为什么不能只看“确实蓝了”就评价成功？答案：属性成功与身份保持是两个维度，应分别评估。

第 14 课：从二维照片到三维人脸

三维顶点是 (x,y,z)，三角面把顶点连接成表面，纹理给表面颜色，相机把三维投影成二维。单张图只有一个视角，背面和真实深度信息不充分，因此重建依赖先验，结果不是对真实头骨的直接测量。

3DMM 把脸写成“平均脸 + 一些变化基底的加权和”：S=平均形状+A_identity×身份系数+A_expression×表情系数。网络预测系数与相机参数，再生成网格。PRNet 预测位置图；3DDFA_v2 进行三维稠密对齐；DECA 研究更详细、可动画化的脸部表达。PRNet、3DDFA_v2、DECA

估计头部朝向不等于恢复个人三维形状。solvePnP 可用少量二维点和一个预设三维模板估计相机姿态；若对每个人用同一个网格，它仍是固定模板。真正的重建演示需要说明输入怎样影响几何、所用权重和基底来源、输出 OBJ/PLY 顶点与面，并从正面、侧面、斜面展示。

OpenGL 是图形渲染接口，PyTorch3D 提供与 PyTorch 结合的三维工具。普通渲染把模型变成图像；可微渲染还使输出误差能通过渲染过程反向传播到形状、相机或材质参数。把 OBJ 存出来不代表已经验证渲染，把二维画线投影不应叫作 PyTorch3D 渲染。

NeRF 以空间位置和观察方向为输入学习密度与颜色，再沿光线积分；通常需要多视角或其他先验。3D Gaussian Splatting 用空间中的可优化高斯元素表示场景，经投影和混合形成图像。它们是神经渲染的重要路线，但“用了单图三维模型”不自动意味着已实现 NeRF 或 3DGS。NeRF、3DGS

练习：程序加载一个固定头模，只根据眼睛坐标让它旋转，算单图三维重建吗？答案：属于姿态估计/模板展示，不能算个体形状重建。把图像纹理贴到固定模型上仍不能改变这个事实。

第 15 课：把算法做成可用应用

本项目采用 Python 标准库 HTTP 服务加浏览器原生 HTML/JavaScript。页面负责图片选择、摄像头帧获取、效果选项和显示；Python 解码输入、调用 OpenCV、生成结果和指标。浏览器发送 JPEG 的 base64 文本，服务器返回处理后的图像。简单结构便于你沿一次请求看懂整个流程。

本地服务只监听回环地址，并校验 Host/Origin、请求体类型与大小、图片格式、强度和阈值范围。输入校验能把用户误操作转化为可理解错误。把服务改为 0.0.0.0 会改变访问范围，不应为了“手机试一下”就跳过身份验证与传输设计。

服务器 app.py 的主要路径：GET /health 检查存活，GET / 返回页面，POST /process 做检测/特效，POST /verify 比较两张照片。当前单进程一次处理一个 CPU 请求，避免共享模型状态并发问题；多人同时用时吞吐受限。先测出瓶颈再增加队列、批处理或服务框架，符合本项目 ponytail full 的最少必要实现原则。

FPS 的定义为 处理帧数/经过秒数，单帧20ms理论串行上限约50 FPS，但这未包含所有环节。视频文件标称30 FPS不表示模型达到30 FPS；离线慢慢处理后按30 FPS编码也能得到流畅播放文件。要同时报告实际耗时、输入/输出帧数和端到端速度。

练习：处理300帧用了60秒，输出视频写30 FPS。模型速度是多少？答案：5 FPS；视频播放时长10秒，不能据此声称30 FPS实时。

第 16 课：Git、GitHub、Docker 与 Jupyter

Git 保存源码历史，GitHub 托管远程仓库。git status 看改动，git diff 看具体差异，git add 选择进入下一次提交的文件，git commit 保存本地快照，git push 发送远程。公开仓库应有 README、LICENSE、环境说明和可重复命令。仓库公开不代表数据集和预训练权重许可也被转换为同一许可证。

git status
git diff
git add app.py web/index.html docs
git commit -m "Document face vision pipeline and evaluation"
git push

这组命令是理解版本控制的示例，提交前逐项看变更。不要 git add . 后才发现摄像头照片、密钥或大权重也被加入。.gitignore 只影响未跟踪文件，对已提交秘密无效；一旦秘密泄露，需撤销凭据，不能仅删除最新文件。

Docker 用镜像描述依赖和应用启动方式，容器是镜像运行起来的实例。Dockerfile 是配方，docker build 是实际制作，docker run 才是运行。因此交付 Dockerfile 不能算构建成功。Windows 上 Docker Desktop 可能依赖虚拟化/WSL，安装客户端也不代表 daemon 可用。

docker version
docker build --target hello -t face-vision-hello .
docker run --rm face-vision-hello

这里应查看 client 和 server 都是否存在，保存 build 与 run 的真实日志；本机Docker在WSL中，上述命令需要在该WSL环境执行。hello是Dockerfile中的阶段，运行的是hello_world.py；远端已有名为hello.py的目录被保留，避免覆盖旧内容。摄像头并不天然能被 Linux 容器直接读取；本项目通过浏览器帧传输的思路可减少设备映射问题，但仍需端口绑定和实际验证。

核心应用的容器也已实际构建运行：docker build --target lab -t face-vision-lab .，随后 docker run --rm -p 127.0.0.1:8765:8765 face-vision-lab。访问宿主8765端口即可转发到容器8765端口。由于应用校验Host端口，若使用8766，映射与程序应一起改为8766；只改外部端口可能得到403。这个镜像包含检测/验证/特效与文档，训练和三维生成依赖仍按对应研究环境安装；成功运行核心镜像不证明所有研究模块都已部署。

Notebook 把文字、代码、结果放在同一文件，适合画训练曲线、展示图像。单元格执行顺序可能混乱，交付前用“Restart and Run All”从头执行；只看画面中有数字不能证明当前代码能重现它。核查 notebook 所用 kernel 的 sys.executable 与命令行环境一致。

练习：本地 commit 成功，GitHub 上却没有文件，缺了哪一步？答案：可能没有 push 或推到了不同分支/远程，先查 git remote -v 和 git status，最后直接读取远程验证。

第 17 课：版本兼容与故障定位

看兼容性要同时看 Python、操作系统、PyTorch、CUDA、torchvision、MMCV 和 MMDetection。MMCV 的编译算子与 PyTorch/CUDA 组合有关，装上“最新版”可能违反 MMDetection 的版本断言。3.3.0 的依赖范围见 官方源码。mmcv-lite 能 import 不代表 mmcv.ops 能训练检测器。

按最小证据链排查：解释器能启动→标准库 SSL 能用→网络能访问目标→库可 import→模型文件不是下载错误页/Git LFS 指针→模型可加载→单张图推理→整批评估。每次只解决当前最先失败的层，不要同时升级十个包。

本次运行发现进程环境缺少 SystemRoot、WINDIR、COMSPEC 会影响 Windows 标准功能、SSL/DNS 与 venv。修复在相关子进程中补齐必要环境，避免随意改全局设置。Chrome 自动化入口不可用属于控制连接问题；API 测试成功不能替代“已在 Chrome 操作成功”。完整实测错误与修复依据见 问题记录。

BytePS 需要 CUDA/NCCL，且官方仓库已归档；单机 CPU 不能用它完成真实分布式训练。ByteNN 未提供公开 SDK 时只能说明 ONNX 类推理模拟。火山引擎云体验需要用户账户、已开通服务与授权凭据；没有调用成功响应就不能写“已体验”。

练习：import cv2 成功但读取模型时报解析失败，应先重装 Python 吗？答案：先检查模型文件大小、哈希、内容和来源，确认不是 HTML 页面或 Git LFS 文本指针；再查版本支持。

第 18 课：怎样写一份经得起追问的报告

报告顺序：问题与目标→数据与许可→模型及处理流程→环境和实验设置→结果→错误分析→限制→下一步。每个数字都能回到命令和原始结果文件。失败也是结果：例如 INT8 没加速、完整数据下载被阻断、浏览器无法连接，都应如实记录。

“识别率98.5%”必须跟随：哪个模型、是否自己训练、哪个数据集版本、多少 pairs、拆分协议、阈值如何选择、检测失败如何处理、均值/标准差。论文原作者结果、同图分数1.0、训练分类准确率100%都不能替代。

汇报时建议现场演示一张正常图、一张没有脸的图、一张侧脸或遮挡图，让观众看到成功与边界。三维展示需要同时给输入、正面和侧面；GAN 展示给目标属性、原图和完整一组输出。最终用验收矩阵回答哪些要求 verified、哪些 blocked，不通过删行制造“全部完成”。

练习：报告只写“本项目达到98.93%，INT8准确率还提高了”，缺少什么？答案：需要声明98.9333%属于预训练SFace第二次选脸实验；自训ArcFace FP32仅52.6667%、INT8为53.0167%。还需写6000对十折、训练折选阈值、首轮预处理变更、失败数量及折间标准差；0.35个百分点变化未经显著性检验，不应称作可靠提升。

综合练习与参考答案

本次实际案例：严格单脸策略在6000对LFW中得到72.25%，有1633对因处理失败计错。分析发现许多图像有多个检测框；第二次实验用“面积最大、并列时距中心最近”的固定几何主体规则，在同一完整pairs集达到98.9333%±0.38873个百分点。两次阈值都仅由训练折选择，首轮完整结果也保留。这里学到的是预处理可能决定整个系统表现；第二次规则受首轮错误分析启发，仍需另一个未用于开发的数据集检验泛化。它也不等于我们从零训练出了同等性能的ArcFace。

python -m research.lfw --backend sface --root data/lfw/lfw --pairs data/lfw/pairs.txt --models models --face-policy largest --on-failure count-incorrect --output reports/lfw-sface-largest.json
  1. 设计一项对齐消融实验。同一模型、同一 pairs、同一阈值选择协议，一组使用对齐，一组只裁框；记录漏检、准确率、TAR/FAR和耗时。不能换模型后把变化都归因于对齐。
  2. 设计量化比较。同一 checkpoint 与输入，预热后重复计时；对比文件大小、特征误差、LFW 指标和 P95。若量化只作用 Linear，要写清覆盖范围。
  3. 诊断贴纸抖动。先可视化原始关键点，区分检测不稳定、坐标缩放错误、视频异步乱序；再考虑平滑或跟踪，而不是盲目增加动画。
  4. 发现训练数据仅两个人各一张。P-K 无法得到有效同人正样本，不应重复拷贝图来制造数据量；增补合法多样照片或明确只做接口检查。
  5. 完成一次诚实提交。保留命令、日志、版本、输入清单、输出哈希和限制；开源前排除受限数据、私人照片和凭据；远程读取文件验证推送。

数学与实验规范补充：把直观解释写准确

1. 向量、距离与ArcFace变量

设未归一化特征为 f∈R^d，范数 ||f||₂=sqrt(Σ_k f_k²)。当范数非零时，单位向量 x=f/||f||₂。实现用很小的正数epsilon保护分母，零向量应视为特征异常并分析，不能当成有效身份表示。对于单位向量x、y，||x-y||₂²=2-2xᵀy；因此余弦越大，欧氏距离越小，两者排序相反但可对应。

ArcFace中：N是batch样本数，C是训练身份类别数，d是特征维数，y_i是第i张图的真实类别，归一化权重w_j代表第j类方向，cos θ_ij=w_jᵀx_i。s>0是logit尺度，m≥0是角度间隔（弧度）。正确类logit为 z_i,y=s cos(θ_i,y+m)，其他类为 z_i,j=s cos θ_i,j；交叉熵 L=-(1/N)Σ_i log(exp(z_i,y)/Σ_j exp(z_i,j))。数值实现使用稳定的log-sum-exp/交叉熵库函数，并对角度端点作保护。m不能无限增大，否则任务过难且可能违反单调区间处理。

推理对比时不需要真实类别y，也不把margin加到两图相似度上；比较的是骨干输出的单位特征。归一化降低特征长度对比较的影响，但不会自动消除光照、遮挡或数据偏差。

2. 检测和关键点指标的分母

IoU=area(B_pred ∩ B_gt)/area(B_pred ∪ B_gt)，框应有正面积；空集或非法框先按协议处理。判断TP前须指定IoU阈值与一对一匹配，重复命中同一真实框不应算多个TP。没有预测框时precision的分母为零，报告应使用工具约定并保留这一事实；不能随意填1。

单张脸K点NME为 NME=(1/(K d_norm))Σ_k ||p_hat_k-p_k||₂，p是标注，p_hat是预测，d_norm>0。再在图像间求平均，不等于先把所有分子分母相加再相除；后者会按脸大小改变权重。300-W外眼角归一与其他基准协议分别记录。使用真实关键点外接框裁剪的评估属于oracle/GT-box条件，不能冒充检测器自动裁剪的端到端误差。

3. FAR、TAR和不确定性

设同人对数为N_same、异人对数为N_diff，阈值t，分数越大越相似。TAR(t)=正确接受同人数量/N_same，FAR(t)=错误接受异人数量/N_diff。本项目首次失败计错协议给每个无法处理的pair记0分，无论该pair原本同人还是异人；因此其保守端到端正确率应按该定义解释，不能直接等同于把所有失败视为“拒绝”的普通二分类准确率。

LFW每折300个负对，一次误接受对应1/300≈0.00333；训练九折有2700负对，分辨率也有限。零次错误只表示在有限样本未观察到，不能证明真实FAR=0。十折标准差描述折间波动，不是95%置信区间；不要把均值±标准差写成“95%可信范围”。跨数据集、跨年龄/照明/设备的泛化需额外测试。

4. 生成模型目标与评价

教学StarGAN训练中的生成器目标包含：让判别器的真假评分倾向真实、使目标属性分类正确、把结果转回原属性时接近输入。设目标标签向量为c、原属性为c_src，重建项可为 ||x-G(G(x,c),c_src)||₁。各项由非负权重组合，权重是实验超参数，必须记录。WGAN-GP中的critic输出实数评分，不是经过sigmoid的“真假概率”；梯度惩罚约束插值样本处的梯度范数。此处采用的是具体实现选择，不等于全部GAN都用同一损失。

FID的标准表达为 ||μ_r-μ_g||₂² + Tr(Σ_r+Σ_g-2(Σ_r^(1/2)Σ_gΣ_r^(1/2))^(1/2))，μ和Σ分别为指定特征器在真实/生成图像上的样本均值与协方差。它把特征分布近似为高斯，估计值受样本量影响；非同一特征器的“FID”不能直接横比。IS可写为 exp(E_x KL(p(y|x)||p(y)))，它既希望单图分类有确定性，又希望全体类别多样；不衡量与某个真实集合的距离，也不保证无记忆复现。

5. 三维、坐标和显示范围

3DDFA回归向量含相机/变换、形状和表情参数。基底系数的绝对大小依训练基底单位，不能直接解释为“脸宽多少毫米”。导出的canonical网格描述模型坐标，projected顶点描述图像投影坐标；两个坐标系的y轴方向、尺度与原点可能不同。WebGL是基于OpenGL ES的浏览器接口；查看器代码与静态渲染图可交付，但目标浏览器中实际交互成功应有单独验证。Khronos说明
